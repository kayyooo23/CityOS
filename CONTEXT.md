# CityOS — контекст проекта для Claude Code

Кратко о файлах в этом репозитории и почему они устроены именно так.

## Файлы

- **cityos-pitch.html** — главная презентация для инвесторов/директоров проекта «Цифровой город». Одностраничный сайт со скролл-анимациями (как у Apple/Linear), НЕ PowerPoint.
- **cityos-splash-v2.html** — отдельное демо загрузочного экрана + главного экрана приложения (само по себе тоже открывается и работает).
- **cityos-home.html / cityos-home-v2.html** — более ранние черновики главного экрана, оставлены для истории.

## Ключевая архитектура cityos-pitch.html

**Сквозной сценарий «ночь → рассвет → день».** Весь бэкграунд страницы (небо, солнце/луна, звёзды, городской силуэт) непрерывно меняется по проценту прокрутки страницы (`window.scrollY / (scrollHeight - innerHeight)`), НЕ по дискретным секциям/порогам. Это сделано намеренно — раньше была версия с переключением по секциям (`data-phase` классы), и на границах секций была заметна резкая "склейка". Текущая версия использует `requestAnimationFrame` + линейную интерполяцию цветов (`lerpColor`) — трогать эту логику нужно осторожно, не возвращаясь к дискретным порогам.

**Два встроенных демо внутри телефонов — оба через Shadow DOM, НЕ iframe.** Изначально демо грузилось через `<iframe src="...">` на другой файл — не работало (просмотрщик блокирует), пробовали `data:` URL в iframe — тоже блокировалось. Итоговое решение: весь HTML/CSS/JS демо-виджета встроен как JS-строки (`DEMO_CSS`, `DEMO_HTML`, `DEMO2_CSS`, `DEMO2_HTML`) и рендерится через `element.attachShadow({mode:'open'})` — так стили демо не конфликтуют с стилями страницы (оба используют похожие имена классов вроде `.sun`, `.moon`), и ничего не зависит от загрузки внешних файлов.

- Первый телефон (`#demoHost`) — статичный сплэш+главный экран (копия cityos-splash-v2.html).
- Второй телефон (`#vdHost`) — интерактивный голосовой сценарий (чат с AI, распознавание речи через `SpeechRecognition` API с запасным сценарием на заранее прописанных репликах, если микрофон недоступен).

**Таймлайны (сценарий переезда + roadmap) — используют карточки с фиксированным светлым фоном** (`.timeline-content` с `background:var(--panel)`), а НЕ прозрачный текст поверх динамического неба. Раньше пробовали красить текст в тон динамического фона — давало нечитаемые/непредсказуемые результаты на скриншотах. Текущее решение надёжнее: текст всегда тёмный на всегда светлой подложке, контраст гарантирован независимо от фазы неба.

## Известная незакрытая задача

Пользователь сообщал, что где-то в презентации текст выглядит немного смещённым влево/вправо ("съезжает") — не диагностировано до конца, нужен свежий скриншот с точным указанием места, прежде чем чинить.

## Стиль работы с пользователем

Пользователь (Данил) — нетехнический CEO, не пишет код сам, работает через AI-ассистента. Объяснения давать простым языком, без вопроса "почему ты не программируешь сам". При визуальных багах — сначала просить скриншот с точным указанием проблемного места, не чинить вслепую (несколько раз это приводило к неправильным правкам).
